## Purpose

We discovered that the nvfp4 input quant operation was severely bottlenecking performance for dense models at small batch sizes. While investigating the flashinfer impl, I noticed that there is logic to [increase the grid size for small M](https://github.com/flashinfer-ai/flashinfer/blob/f0592411a3478d0548d62f7c877046499caf8d95/csrc/nv_internal/cpp/kernels/quantization.cu), based on the swizzled layout to help out with the padding ops. Adding that "effective row" calculation greatly improved bs<32 performance.

I also found that there was some redundant computation in the `cvt_quant_to_fp4_get_sf_out_offset` inner loop, so pulled that out and replaced many of the division operations that `nvcc` wasn't optimizing into bitwise ops.

I added a new benchmark script for the quantization op itself for easy microbenchmarks: `python benchmarks/kernels/bench_nvfp4_quant.py`
