## Summary

The Triton attention backend incorrectly allowed FP8 query quantization for
per-tensor KV cache mode — queries were quantized but the kernel ignored the scales,
producing incorrect results.

This PR fixes the issue by adding proper Q scale support to the kernel. When
Q is FP8 and the KV cache uses FP8 per-tensor mode, the kernel now folds
`q_scale * k_scale` into the attention score scale and applies `v_scale` to
the output accumulator.

A new `Q_IS_FP8` constexpr kernel parameter enables compile-time
elimination of the Q descale path when not applicable, avoiding any
overhead for bf16/fp16 query paths.

## Changes

- **`vllm/v1/attention/ops/triton_unified_attention.py`**: Add `q_scale`
  pointer and `Q_IS_FP8` constexpr to `kernel_unified_attention`. Derive
  `USE_FP8_Q_DESCALE` constexpr to guard all scale loads/applies. Pass
  `Q_IS_FP8` from the launcher based on `q.dtype`.
- **`vllm/v1/attention/backends/triton_attn.py`**: Pass `layer._q_scale` as
  `q_descale` when Q is FP8 with per-tensor KV cache. Remove the stale
  `_q_scale_float == 1.0` assertion.
- **`tests/kernels/attention/test_triton_unified_attention.py`**: Update the
  FP8 parametrization to use non-1
