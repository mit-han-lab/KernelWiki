## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
The performance of gptq/awq marlin kernel is low when n is small. The reason is that when n is small, the `barrier_acquire` and `barrier_release` cost too many time.

The case where n is small often occurs during inference using larger tensor parallelism or in some special models. For example, in deepseek-v3 model, the shape of `kv_a_proj_with_mqa` is k=7168 and n=576.

This PR add an argument `use_atomic_add` to marlin kernel, so that we don't require `barrier_acquire` and `barrier_release` anymore.
