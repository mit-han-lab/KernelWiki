## Purpose
- Fix CUDA illegal memory access in LoRA MoE pipeline when `max_loras` equals the number of real active LoRAs and the batch also contains base-model tokens (e.g. the default `max_loras=1` with any mixed batch).
- Bump three grid dimensions in `csrc/moe/moe_align_sum_kernels.cu::moe_lora_align_block_size` from `max_loras` to `max_loras + 1` (commit 1), mirroring what #32277 did for the Triton _fused_moe_lora_kernel grid.
- Add a defensive `lora_id >= max_loras` guard to the three C++ LoRA align kernels (commit 2), mirroring the equivalent guard in the Triton kernel , and add a regression test.
- As mentioned in https://github.com/vllm-project/vllm/pull/40044#issuecomment-4286284156, this PR also fix the root cause for https://github.com/vllm-project/vllm/issues/40038
- Refs #32235.

## Why this isn't duplicating an existing PR
- #32277 (merged) and #35636 (open) fix the `Triton _fused_moe_lora_kernel` grid. This PR fixes the C++ align kernel (moe_lora_align_block_size) grid, which is a separate kernel in the same pipeline with the same off-by-one symptom. Neither existing PR touches csrc/moe/moe_align_sum_kernels.cu.
