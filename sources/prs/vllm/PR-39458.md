# Purpose
While profiling DeepSeek-V3.2 + NVFP4 with MTP > 1 speculative decoding, I noticed that `_prepare_decode_tensors` in `vllm/v1/attention/backends/mla/indexer.py` was adding per-step overhead from pytorch ops like `repeat_interleave`. This function is called once per decode step to build MLA attention metadata, and the expensive path is taken whenever decode lengths exceed what the kernel natively supports, which is 2. This is the common case for speculative decoding with MTP > 1, where the target model validates multiple proposed draft tokens.

I realized that the `if` branch can be further split into the uniform decode length and variable decode length cases. During speculative decoding with uniform decode lengths (the common case, because the target model validates the N speculated tokens from the draft model), we can simplify the ops considerably. I decided to fuse those ops into a single triton kernel.
