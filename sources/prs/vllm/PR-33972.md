## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
When `dtype=float16`, due to the smaller dynamic range of float16, data overflow can easily occur during GEMM, leading to inference errors.
Therefore, we dynamically scale the input before GEMM to prevent data overflow.

Fix: https://github.com/vllm-project/vllm/issues/33560 https://github.com/vllm-project/vllm/issues/33461

<!-- markdownlint-disable -->

## Purpose

The nvfp4 model supports the use of `dtype=float16`.

## Test Plan

I test models: /RedHatAI/Qwen3-30B-A3B-NVFP4,  /RedHatAI/Qwen3-32B-NVFP4 , /RedHatAI/Qwen3-32B-NVFP4A16 , /RedHatAI/Qwen3-8B-NVFP4.

Before this patch, the input activations of dense models ( /RedHatAI/Qwen3-32B-NVFP4, /RedHatAI/Qwen3-32B-NVFP4A16 , /RedHatAI/Qwen3-8B-NVFP4) have NaN, and MoE models works normal.
