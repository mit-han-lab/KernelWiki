## 📌 Description

<!-- What does this PR do? Briefly describe the changes and why they’re needed. -->
The existing FlashInfer top-p renormalization uses a ternary-search-based algorithm that requires ~30 iterative passes over the full vocabulary, with each pass reading from global memory. It also only uses one thread block per batch row, severely limiting parallelism. As shown in the benchmark below, top-p is ~30-60x slower than top-k on the same data:
```
