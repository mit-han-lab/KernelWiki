## Problem:

In SGLang, we pass [cos_sin_cache](https://github.com/sgl-project/sglang/blob/1acc1f561ae859c94c3da746d629d1f60cbe00b6/python/sglang/srt/layers/rotary_embedding.py#L147) with the shape `(max_len, rot_dim)` to RoPE kernel. However, flashinfer accepts [cos_cache and sin_cache](https://github.com/flashinfer-ai/flashinfer/blob/aab87153c3efb4489db8b17be9f37ef6635345aa/flashinfer/rope.py#L1058) with both the shape as `(max_len, rot_dim)`. Though it is possible to convert `cos_sin_cache` to `cos_cache` and `sin_cache`, it introduces performance overhead and potential incompatibility with existing SGLang models. Therefore, this PR makes necessary changes to provide an **exact kernel interface** with existing SGLang's with **better performance**.
