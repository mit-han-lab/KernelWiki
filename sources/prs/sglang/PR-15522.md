# Updated Summary

  Optimize FP8 MLA KV cache writes in NSA decode by:
  - skipping `torch.cat([k_nope, k_rope])` in the FP8 path, and
  - reusing the existing `set_mla_kv_buffer_triton` two-tensor write kernel.

  **No new Triton write kernel is added in the final version.**

  ## Motivation

  In DeepSeek-V3.2 decode, each step writes FP8 MLA KV cache per layer. The baseline path incurs noticeable CPU-side overhead when using PyTorch fancy indexing (`index_put_`) for small writes.

  ## Changes

  1. **Add `quantize_k_cache_separate(k_nope, k_rope)`** in `python/sglang/srt/layers/attention/nsa/quant_k_cache.py`.
     - Reuses existing fast quantization kernel (`_quantize_k_cache_fast`) without requiring an upstream concat.
     - Returns `(nope_part, rope_part)` as uint8 byte views, matching the MLA KV buffer layout.

  2. **Update FP8 NSA KV write path** in `python/sglang/srt/mem_cache/memory_pool.py`:
     - Remove upstream concat.
     - Reuse `set_mla_kv_buffer_triton(kv_buffer, loc, nope_part, rope_part)` for FP8 writes.
