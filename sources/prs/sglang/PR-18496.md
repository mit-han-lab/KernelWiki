## Motivation

Fix JIT kernel compilation failures on newer GPUs (e.g., Blackwell sm_100) when `nvidia-smi` reports incorrect compute capability due to outdated driver metadata.

### Problem

When the NVIDIA driver is not fully updated to recognize new GPU architectures, `nvidia-smi` reports wrong compute capability:

```bash
$ nvidia-smi --query-gpu=compute_cap --format=csv
8.9   # ❌ Wrong! Actual GPU is sm_100 (Blackwell)
```

However, PyTorch's CUDA Runtime API correctly detects the GPU:

```python
>>> torch.cuda.get_device_capability(0)
(10, 0)  # ✅ Correct
```

`tvm_ffi` uses `nvidia-smi` internally to detect GPU architecture ([source](https://github.com/apache/tvm-ffi/blob/437323c/python/tvm_ffi/cpp/extension.py#L148)), generating incorrect gencode flags:

```bash
nvcc -gencode=arch=compute_89,code=sm_89 ...  # ❌ Wrong target
```

Related upstream issue: https://github.com/apache/tvm-ffi/issues/430

This causes:
1. **Compilation error**: PDL asm (`griddepcontrol`) in `utils.cuh` is emitted for sm_89 target, but PDL requires sm_90+ → `ptxas` rejects it
2. **Runtime error**: Even if compilation succeeds, sm_89 binary cannot run on sm_100 GPU → "no kernel image available"
