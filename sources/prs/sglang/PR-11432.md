## Motivation
There are two motivations for implementing Expert Specialization Grouped GEMM.
### 1. CUTLASS MoE Benchmark
When I used [benchmark](https://github.com/sgl-project/sglang/blob/main/python/sglang/test/test_cutlass_moe.py) to test the performance of FP8 Blockwise Grouped GEMM, I found that the performance was poor when the batch size was 512 to 1024:
<img width="3840" height="2112" alt="test_cutlass_moe" src="https://github.com/user-attachments/assets/c91777d2-fccf-469c-a852-7a21da2fdf6b" />
The reason is that at this time FP8 Blockwise Grouped GEMM uses a larger TiledMMAShape: https://github.com/sgl-project/sglang/blob/a1a20b4c7cb86f81296ece3c4cb265584be1c179/sgl-kernel/csrc/moe/fp8_blockwise_moe_kernel.cu#L488-L489
At this time, the number of tokens that each expert needs to process is very small (M is very small), and using a large TiledMMAShape will result in additional unnecessary calculations.
