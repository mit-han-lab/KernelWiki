## Summary

Split GEMM backend-specific logic out of the shared tile op path. The common `src/op/gemm.cc` now resolves backend implementations through a registry, while CUDA, ROCm, and CPU selection/lowering details live under their own backend directories.

Add a Python GEMM implementation registry under `tilelang.backend`, with per-backend modules registering the implementation classes used by GEMM infer-layout and lowering.

## Why

This keeps hardware instruction selection and backend-specific GEMM implementation choices out of the generic tile op code, matching the backend split pattern used by copy and making future backend-specific GEMM changes more localized.
