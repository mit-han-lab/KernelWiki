## Summary
- add end-to-end `T.int4` support for the `T.gemm` frontend path and switch the int4 GEMM tests to the generic tensor core emitters
- lower eligible global-to-shared async copies directly to their final packed `cp.async` width during async copy injection instead of relying on a later vectorization pass to widen them
- add an int4 GEMM example and a frontend compilation test, and remove the stale dead `CPAsyncStoreRewriter` path

## Details
- `TensorCoreIntrinEmitter` / `TensorCoreIntrinEmitterWithLadderTransform` can now infer the sub-byte MMA path from the input dtype, so the int4 tests no longer depend on the dedicated INT4 emitter classes
- `InjectPTXAsyncCopy` now computes packed transfer width in bits, requires exact byte alignment, and folds vectorized copy loops directly into a single final-width `ptx_cp_async` when the transfer is legal
- the late vectorization passes no longer try to widen already-materialized `cp.async` ops
- added `examples/gemm_int4/example_tilelang_gemm_int4.py` and `testing/python/kernel/test_tilelang_kernel_int4_gemm.py` to cover the new frontend path
